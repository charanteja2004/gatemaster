A dense index has an entry per record; a sparse index has one per block and needs the file to be sorted on the indexed key.

Only one clustered index per table, because it dictates the physical order of the rows. Everything else is a secondary index and must be dense.

B+ trees

  • All records live in the leaves, which are chained for range scans.
  • Internal nodes hold only separator keys, so fan-out is high and the tree is shallow.
  • Order n means each node holds up to n−1 keys and n pointers.

A B+ tree of order 100 and height 3 indexes about a million records, which is why disk-based indexes are B+ trees rather than binary trees.
