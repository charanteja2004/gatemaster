Database Recovery

Recovery restores the last consistent state after a crash, using a log written before the data pages.

Write-ahead logging: the log record reaches stable storage before the change it describes. Without that rule, a crash could leave a change with no record of how to undo it.

  • Undo: roll back transactions that had not committed.
  • Redo: reapply transactions that had committed but whose pages were not yet written.
  • Checkpoints bound how far back recovery must read.

Deferred update writes nothing until commit and so never needs undo. Immediate update writes as it goes and needs both.
