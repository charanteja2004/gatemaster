Doubly Linked List

A doubly linked list gives every node a pointer to its predecessor as well as its successor. That one extra pointer is what allows deletion of a node in O(1) when you already hold a pointer to it — something a singly linked list cannot do.

struct Node {
    int          data;
    struct Node *prev;
    struct Node *next;
};

The head's prev and the tail's next are both NULL. In a circular doubly linked list they point at the tail and the head respectively.

Insertion

Inserting node q after node p needs four pointer writes, and the order matters — write to p->next last or you lose the rest of the list:

q->next = p->next;
q->prev = p;
if (p->next != NULL)
    p->next->prev = q;
p->next = q;

Deletion

To delete node p, given only p:

if (p->prev != NULL) p->prev->next = p->next;
else                 head           = p->next;

if (p->next != NULL) p->next->prev = p->prev;

free(p);

This is the whole point of the structure. In a singly linked list you must first walk from the head to find the predecessor, making deletion O(n).

Cost of each operation

OperationSingly linkedDoubly linked
Insert at headO(1)O(1)
Insert at tail (tail pointer kept)O(1)O(1)
Delete a given nodeO(n)O(1)
Delete from tail (tail pointer kept)O(n)O(1)

Traverse backwardsNot possibleO(n)
Extra memory per node1 pointer2 pointers

Trade-offs

  • Cost: one extra pointer per node. On a 64-bit machine that is 8 more bytes per element, which matters when the payload is small.
  • Maintenance: every insertion and deletion has to keep two pointers consistent, so there are more ways to write a bug.
  • Benefit: O(1) deletion given a node, and backward traversal.

Where it is used

  • LRU cache — a hash map to nodes plus a doubly linked list gives O(1) lookup and O(1) move-to-front, which is the standard interview and GATE construction
  • Browser history, undo/redo stacks, music playlists
  • Deques, and the free lists inside many memory allocators
  • The scheduler queues and buffer caches of most operating systems

XOR linked list

A memory-saving variant stores prev XOR next in a single field, recovering both pointers by XOR-ing with the address you arrived from. It halves the pointer overhead but breaks garbage collection and pointer-safety analysis, so it is a curiosity rather than a practical structure — worth knowing only because it appears in questions.
