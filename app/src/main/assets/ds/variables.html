Variables and Storage Classes in C

A variable is a named region of memory. In C, four properties of that region are decided separately, and GATE questions almost always turn on one of them: its scope (where the name is visible), its lifetime (how long the memory exists), its linkage (whether other translation units can see it), and its initial value.

Declaration against definition

  • A declaration introduces a name and its type: extern int x;
  • A definition also allocates storage: int x;

A variable may be declared many times but defined exactly once across the whole program.

The single most examined line in this table: an uninitialised local variable holds garbage, but an uninitialised global or static variable is zero. Reading the local before assigning to it is undefined behaviour.

static does two different jobs

Inside a function, static extends lifetime — the variable keeps its value between calls and is initialised only once:

void counter(void) {
    static int n = 0;   /* initialised once, at program start */
    n++;
    printf("%d ", n);
}
/* three calls print: 1 2 3 */

At file scope, static instead restricts linkage: the name becomes private to that .c file and cannot be reached with extern from another. The keyword is the same; the effect is not.

register

A hint that the variable is used often and might live in a CPU register. The compiler is free to ignore it, and modern compilers almost always do — they allocate registers better than the programmer can. The one part of the rule that still binds: you cannot take the address of a register variable, so &x is a compile error.

An inner declaration shadows an outer one of the same name for the rest of the inner block:

int x = 10;
int main(void) {
    int x = 20;
    {
        int x = 30;
        printf("%d ", x);   /* 30 */
    }
    printf("%d ", x);       /* 20 */
    return 0;
}

String literals sit in the read-only region, which is why char *s = "abc"; s[0] = 'A'; is undefined behaviour and typically segfaults, while char s[] = "abc"; copies into a modifiable array and is fine. That distinction appears in GATE regularly.

Common traps

  • static int a[10]; is zero-filled; int a[10]; inside a function is not.
  • A static local is initialised once, not on every call.
  • Returning the address of a local is a dangling pointer — the stack frame is gone.
  • extern int x = 5; at file scope is a definition, not a declaration.
