Paging in Operating System

Paging is a memory management scheme that removes the requirement for a process to occupy one contiguous block of physical memory. Physical memory is cut into fixed-size blocks called frames, the process’s logical address space is cut into blocks of exactly the same size called pages, and any page may be placed in any free frame. Because a page fits any frame, the operating system never has to hunt for a large enough contiguous gap.

The two address spaces

  • Logical address (also called a virtual address): the address the CPU produces while running a process. It is an offset into that process’s own address space, not a location in RAM.
  • Logical address space: the set of every logical address a process can generate. If a logical address is m bits wide, the space holds 2m addressable units.
  • Physical address: an actual location in main memory, the address that finally reaches the memory unit.
  • Physical address space: every physical address the machine has. If a physical address is p bits wide, the space holds 2p units.

The two are independent. A logical address space is frequently larger than the physical one — that is the whole point of virtual memory, and it is why the example below has 13-bit logical addresses on a machine with only 12-bit physical addresses.

How an address is translated

Page size is always a power of two, say 2n units. That choice is what makes translation cheap: the low n bits of a logical address are already the offset within the page, and the bits above them are already the page number. No division is needed — the address simply splits.

  • Page number (p): the upper m − n bits. It indexes the page table.
  • Page offset (d): the lower n bits. It says which unit inside the page is wanted.

The page table, one per process, maps each page number to the frame number holding that page. The hardware that performs the lookup is the memory management unit (MMU). It replaces the page number with the frame number and leaves the offset untouched, because a page and a frame are the same size, so a unit sits at the same offset in both.

Working out the bit widths

Almost every exam question on paging is this one calculation. Given a logical address of m bits, a physical address of p bits, and a page size of 2n units:

  • Page offset = frame offset = n bits.
  • Page number = m − n bits, so the process has 2m−n pages.
  • Frame number = p − n bits, so memory holds 2p−n frames.
  • The page table has one entry per page: 2m−n entries, each holding a frame number of p − n bits plus a few control bits.

Worked example. Logical address = 13 bits, physical address = 12 bits, page size = frame size = 1 K words = 210 words.

  • Logical address space = 213 = 8 K words.
  • Physical address space = 212 = 4 K words.
  • Offset = 10 bits.
  • Page number = 13 − 10 = 3 bits, so there are 23 = 8 pages.
  • Frame number = 12 − 10 = 2 bits, so there are 22 = 4 frames.
  • The page table has 8 entries, each at least 2 bits wide.

Note that the number of pages depends only on the logical address space and the page size. The physical address space never enters that calculation — it decides how many frames exist, which is a different number, and here a smaller one.

The translation lookaside buffer

The page table lives in main memory, so a naive lookup costs two memory accesses for every one the program asked for: one to read the page table entry, one to fetch the data. The TLB is a small associative cache of recently used page-to-frame mappings that removes the first access on a hit.

  • It is high-speed associative memory: every tag is compared at once, so a lookup takes constant time regardless of how many entries it holds.
  • Each entry is a pair — a tag (the page number) and a value (the frame number).
  • With TLB access time t, memory access time M, and hit ratio h, the effective access time is h(t + M) + (1 − h)(t + 2M).

What paging costs

  • It eliminates external fragmentation. Free memory is a set of identical frames, and any page fits any frame, so free space is never unusable merely because it is scattered.
  • It causes internal fragmentation. A process rarely fills its last page exactly. The waste is at most one unit short of a full page per process, and averages about half a page — which is why very large pages are a poor trade.
  • The page table itself consumes memory. One entry per page, per process. A large logical address space with small pages produces a table too big to keep in memory outright, which is what multi-level and inverted page tables exist to solve.
  • Every access needs a translation. Without a TLB that doubles memory traffic, and the page table must be reloaded on a context switch.

Points that are commonly confused

  • Paging removes external fragmentation and introduces internal fragmentation. Segmentation does the opposite. Getting these the right way round is worth a mark on its own.
  • The offset width is fixed by the page size alone, and it is identical on both sides of the translation.
  • Pages and frames are always equal in size. If a question gives them different sizes, it is not describing paging.
  • Each process has its own page table, which is what keeps one process from addressing another’s memory.
