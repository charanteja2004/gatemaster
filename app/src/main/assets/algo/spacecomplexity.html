Space Complexity

Space complexity is the total memory an algorithm needs as a function of the input size, counting both the input itself and everything the algorithm allocates on top of it.

Space complexity = input space + auxiliary space

Auxiliary space is the one that is usually asked

Auxiliary space is the extra memory an algorithm uses beyond the input. Because the input array is already there whatever you do, comparisons between algorithms are almost always comparisons of auxiliary space. When a question says "space complexity of merge sort", the expected answer is nearly always the auxiliary space, O(n).

Space complexityAuxiliary space
Bubble sortO(n)O(1)
Merge sortO(n)O(n)

Both are O(n) overall, and the two algorithms look identical on that measure. Auxiliary space is what distinguishes them.

The recursion stack counts

Every pending recursive call holds a stack frame, so the maximum recursion depth is part of auxiliary space. This is the most common source of wrong answers.

int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

This uses O(1) memory per frame but reaches depth n, so its auxiliary space is O(n) — not O(1). A loop doing the same job would be O(1).

Sorting algorithms

AlgorithmAuxiliary spaceWhy
Bubble, Selection, InsertionO(1)A few loop variables; swaps in place
Heap sortO(1)Heapifies the array in place, iteratively
Quick sortO(log n) average, O(n) worstRecursion stack; worst case when partitions are maximally unbalanced
Merge sort (array)O(n)Temporary array for the merge
Merge sort (linked list)O(log n)Merging needs no temporary; only the stack
Counting sortO(k)k = range of the key values
Radix sortO(n + k)Buckets plus output array

Quick sort's O(log n) becomes O(n) if the recursion is not arranged carefully. Recursing on the smaller partition first and looping on the larger one bounds the stack at O(log n) even in the worst case — a standard follow-up question.

"In place" is not the same as O(1)

An algorithm is in place if it transforms the input using only a constant amount of extra space, or by common convention O(log n). So heap sort is in place; merge sort on an array is not. Quick sort is usually called in place despite its O(log n) stack, which is why the term is worth pinning down before answering.

0/1 Knapsack (rolling row)O(W)

That last pair is a useful pattern: many dynamic-programming tables only ever read the previous row, so the table collapses from O(nW) to O(W) without changing the running time.

Worked example

void f(int n) {
    int a[100];          // O(1)   -- fixed size, independent of n
    int *b = malloc(n * sizeof(int));   // O(n)
    if (n > 0) f(n / 2); // stack depth O(log n)
}

The array is a constant 100 integers however large n is, so it contributes O(1). The allocation contributes O(n) and, because it is never freed before the recursive call, all O(log n) frames hold one at once — giving O(n) total for the allocations plus O(log n) for the frames, so O(n) overall.
