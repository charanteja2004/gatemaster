Merge Sort

Split the array in half, sort each half recursively, then merge the two sorted halves in linear time.

T(n) = 2T(n/2) + Θ(n) ⟹ T(n) = Θ(n log n)

Θ(n log n) in all cases

O(n) for the merge buffer

The guarantee is the point: unlike quick sort there is no bad input. The price is the extra array, which is why quick sort is usually preferred in memory-tight code.

Stable if the merge takes from the left half when the two fronts are equal. Reversing that tie-break silently breaks stability.

Merging [1, 4, 7] and [2, 3, 9] compares 1-2, 4-2, 4-3, 4-9, 7-9 and copies the rest: at most n−1 comparisons for n elements.
